# Threat model

This is a **research prototype on synthetic data** (Synthea). This document says what it is designed to withstand,
what it assumes, and — just as important — what it does **not** defend against. Where a claim is backed by a test,
the test is named. The formal statements (security theorem with the explicit leakage list L1-L13, end-to-end DP
theorem) are in [`SECURITY_THEOREMS.md`](SECURITY_THEOREMS.md).

## 1. Assets

| asset | where | sensitivity |
|---|---|---|
| per-patient records (history, reports, prescriptions) | each hospital's own SQLite file | highest |
| the linkage key (`national_id`) and demographics | encrypted columns in every hospital DB | highest |
| per-patient predicate results ("patient *k* took drug Y") | in memory at a hospital; secret-shared on the wire | high |
| exact aggregate counts / sums | **nowhere**: the hospitals add their noise shares inside the MPC, only the noisy cell is opened | medium — releasing them exactly enables differencing |
| each hospital's DP noise share | drawn and secret-shared by that hospital; never opened on its own | high — subtracting enough of them would expose the exact aggregate |
| a requester's privacy budget | coordinator DB (ledger) | integrity-critical |
| the audit trail | coordinator DB | integrity-critical |
| keys: hospital data keys, JWT secret, audit key, TLS keys | `./secrets` | critical |

## 2. Actors and trust assumptions

| actor | assumed to be | consequence |
|---|---|---|
| **Hospital A / B / C** | **honest-but-curious** (semi-honest): follows the protocol, tries to learn from what it sees. For each query two hospitals compute and the third deals the Beaver triples | no defence against a hospital that *deviates* (sends wrong shares, probes with crafted PSI lists) |
| **Coordinator** | honest-but-curious. It holds **no protocol secret**: it sees no exact aggregate (only exact + noise) and deals no triples. It still holds the JWT and audit keys and runs the budget ledger | a compromised coordinator can forge or replay queries without charging anyone, defeat authentication and the audit log — but it cannot read an exact count or another hospital's data |
| **Requester** (researcher / clinician) | **potentially malicious**: crafts differencing queries, repeats queries to average noise, tries role escalation | defended by schema validation, DP, the ε-ledger, k-threshold, RBAC |
| **Auditor** | honest; read-only; cannot query | — |
| **Network attacker** | can observe and modify traffic between services and clients | defended by (mutual) TLS |
| **Offline attacker** (stolen disk / backup) | can read database files, not the running service | defended by AES-GCM at rest |
| **Collusion** | the coordinator may collude with **any one** hospital (Theorem 1 and 2b); **two hospitals must not collude** (honest majority); requesters may collude with each other but each account has its own budget | see §4 |

## 3. What the design defends against

| threat | defence | evidence |
|---|---|---|
| A hospital reads another's patient list during linkage | PSI by commutative encryption; a hospital learns which of its own patients each other member holds and the overlap sizes (L7), nothing about patients it does not hold | `tests/test_psi.py` (incl. the HMAC dictionary-attack comparison) |
| A hospital or the coordinator reads per-patient predicate results | additive secret sharing + Beaver multiplication; triples come from a third hospital (P0 gets a seed, P1 the corrections), openings flow only between the two computing hospitals; the coordinator receives one random-looking share per cell | `tests/test_mpc_service.py` (wire scan: no identifier and no value < 2³⁰ in any MPC message; mutation test proves the scan has teeth; only the dealer may deliver triples) |
| The coordinator reads an exact aggregate | DP noise generated by the hospitals in shares and added **inside** the MPC; hospitals refuse an exact computation and any plan above their per-query cap, sized for fewer colluders than they tolerate, or whose budgeted groups leave an output cell out | `tests/test_mpc_service.py::test_noisy_run_never_opens_the_exact_value`, `::test_hospitals_refuse_weak_or_missing_noise`, `::test_hospitals_refuse_noise_that_needs_every_share_honest`, `tests/test_distributed_dp.py::test_hospitals_refuse_a_plan_that_leaves_a_cell_outside_the_budget` |
| The coordinator tells each hospital a different plan (e.g. "histogram" to some, "sum" to the owner) to get a weaker total | every hospital-to-hospital message carries a digest of the computation header; a mismatch is refused; the owner checks that the aggregate matches its slice | `tests/test_mpc_service.py::test_hospitals_detect_a_coordinator_that_tells_them_different_plans`, `::test_owner_rejects_an_aggregate_that_does_not_match_its_slice` |
| The coordinator learns cohort or list sizes | the linked index and every PSI list are padded to a public bound M with empty rows / random dummy identifiers; the coordinator sees only M | `tests/test_psi.py::test_lists_are_padded_to_the_public_bound`, `::test_linkage_cohort_sizes_are_exact_but_stay_at_the_hospitals` |
| The coordinator times a hospital (how many patients matched, how big its noise share was) | calls that touch patient data or draw noise answer at a public deadline; Laplace scales above a cap are refused so the deadline stays bounded | `tests/test_deadlines.py` |
| The last PSI hop learns a hospital's record order | lists are shuffled with fresh randomness before the ring | `tests/test_mpc_service.py::test_psi_lists_enter_the_ring_in_a_fresh_random_order` |
| The coordinator plus one hospital subtract that hospital's noise | shares sized so that any 2 of the 3 already give the full ε (tolerance t = 1) | `tests/test_distributed_dp.py`; differencing attack, "coordinator + 1 hospital" column in RESULTS.md |
| A hospital learns another hospital's *query predicate* | each hospital is sent only its own slice (+ the shared condition code) | `test_each_hospital_receives_only_its_own_predicate` |
| A requester extracts rows | the query language has no row-level construct; `extra="forbid"`; hospitals re-validate and expose no row endpoint | `tests/test_schemas.py`, `tests/test_hospital_api.py`, `tests/test_secure_api.py` |
| Differencing / membership inference on released numbers | distributed discrete-Laplace / discrete-Gaussian noise calibrated to sensitivity, exact integer samplers | `tests/test_dp.py`, `tests/test_distributed_dp.py`; attack demos in Phase 6 |
| Averaging out the noise by repeating a query | per-user ledger (zCDP + pure basic composition, Theorem 2) refuses queries once the budget is spent | `tests/test_dp.py` (40-thread race, dual-filter rules), `tests/test_secure_api.py` (14 parallel requests, budget 10) |
| Tiny cells identify individuals | k-threshold (k = 10) on the **noisy** count — post-processing, so the suppress/release decision is inside the DP guarantee | `tests/test_dp.py`, `tests/test_private_service.py::test_suppression_is_decided_on_the_noisy_count` |
| Unauthenticated / escalated access | JWT (pinned alg, required claims, expiry), RBAC from `policy.yaml`, login throttle | `tests/test_security.py`, `tests/test_secure_api.py` |
| Theft of database files | AES-256-GCM on sensitive columns, key outside the data directory | `tests/test_encryption.py` (raw DB bytes scanned; plaintext control) |
| Eavesdropping / tampering between services | TLS 1.2+, hospitals require client certificates from our CA | `tests/test_e2e_tls.py` |
| A peer issuing control commands or impersonating another service | signed 60-second service tokens; control endpoints coordinator-only; peer endpoints check the named `sender` | `tests/test_secure_api.py::test_hospitals_only_obey_the_coordinator_and_the_named_sender` |
| Editing / deleting / reordering / forging audit entries | HMAC hash chain + append-only triggers + `verify_chain` | `tests/test_security.py` (every tamper case) |
| Budget lost on failure, or spent twice; a data-dependent abort used as a free channel | reserve → commit / refund lifecycle; a computation that aborts after any hospital shared is charged; integer micro-ε / pico-δ / nano-ρ | `tests/test_dp.py`, `tests/test_private_service.py::test_a_failure_after_the_hospitals_shared_their_data_is_charged` |
| The coordinator regenerates a hospital's FL noise from the seed it chose | FL noise comes from hospital-private randomness; a round is released either plainly or as shares, never both; every round includes the whole federation (a round of one would "aggregate" a single update); strict mode refuses plain updates | `tests/test_federated.py::test_the_coordinator_cannot_regenerate_the_dp_noise_or_take_both_releases`, `::test_fl_endpoints_obey_the_service_identity_rules` |

## 3b. Attacks that were actually run (details and numbers: `evaluation/RESULTS.md`)

| attack | result | what it teaches |
|---|---|---|
| **Differencing** — two large queries differing by one patient | **100%** attacker accuracy with exact answers *and with the k-threshold alone*; with the noise drawn inside the MPC: 51.4% at ε = 0.1, 60.1% at ε = 1, 98.2% at ε = 5, matching the exact theory and below the DP ceiling; a coalition that knows one hospital's noise share does a little better (theory 64.0% at ε = 1), still below the ceiling | the k-threshold stops only the *direct* small-cohort question; DP is what stops differencing; **a large ε per query is no protection** |
| **Re-identification** of a "de-identified" release | 46% of a names-removed Hospital-A table re-identified on birth year + sex + ZIP (94% precision); 0.2% after generalising age and ZIP | removing names is not anonymisation — which is why the system exports no rows at all |
| **Budget exhaustion** — repeat a query to average out the noise | error ∝ 1/√N without a limit; the ledger refuses at query 21 (budget 10, ε = 0.5) | per-requester composition accounting is essential — and does not stop colluding accounts |
| **HMAC dictionary** (bonus) | recovers all 2,862 of B's patients (incl. 463 never seen by A); 0 of 125 against PSI | the case for PSI over shared-key pseudonyms |

## 4. Known limitations (what this prototype does NOT protect)

**Cryptographic protocols**
* **Semi-honest only.** No zero-knowledge proofs or MACs: a hospital can feed PSI a fabricated list to test whether a specific patient is shared, or send a wrong output or noise share and silently corrupt (or bias) a result.
* **Honest majority of hospitals.** Two colluding hospitals break input privacy: the dealer knows the triple masks and a computing hospital sees the openings, so together they read the third hospital's indicator vectors; the two computing hospitals together hold both shares of everything. The coordinator may collude with any *one* hospital (Theorem 1). Generating triples without a dealer (OT / HE between the two computers) would remove the dealer from the trust base; it is not implemented.
* **Triple security is computational.** P0's triple shares come from a SHAKE-256 expansion of a 32-byte seed (a PRG assumption); the previous dealer-free-of-assumptions design sent explicit triples.
* **PSI output is pairwise.** Every hospital receives every other hospital's tag set, so it learns which of *its own* patients each other hospital holds (not only the full intersection) and the sizes of the other hospitals' overlaps. List sizes and the linked-cohort size `m` are hidden from the coordinator and the network by padding to the public bound M (4,608), but a hospital still learns every overlap size of a linkage it takes part in, so the coordinator together with one hospital knows them all once a three-hospital linkage has run; and the coordinator still sees the query *shape* (participants, number of output cells, noise plan). These are leakage items L6-L8 in SECURITY_THEOREMS.md and are **not** protected by DP. A shuffled PSI with oblivious placement would close the per-patient part (`LEAK_FIXES.md` §2.3); it is not implemented. Every hospital must have at most M patients.
* **Short exponents** (256 bit) over a 2048-bit group — standard for MODP groups, but not "full-size exponent" DDH. The test group `test768` is deliberately insecure and used only by tests.

**Differential privacy**
* **Distrust costs accuracy.** With collusion tolerance t = 1 every released value carries 1.5× the noise variance a trusted coordinator would add (≈1.3× the mean absolute error for Laplace); t = 0 restores central accuracy but lets the coordinator plus one hospital see past the noise. Measured in RESULTS.md.
* **No federation-wide budget.** Each requester has a budget; the coordinator sees every requester's noisy outputs and nothing caps their total (Theorem 2b degrades with the number of accounts). Hospitals cap each *query* (ε ≤ 2, Gaussian (2, 10⁻⁴)) but do not count queries, so a *malicious* coordinator could run unlimited capped queries and average them. A hospital-side zCDP odometer would close this; it is not implemented.
* **The k-threshold is fuzzy at the boundary.** It now tests the noisy count (closing the old exact-count leak), so a cohort just above k is sometimes suppressed and one just below sometimes released.
* **Several accounts are several budgets.** No result caching, so the same question asked in another phrasing spends budget again (that is the intended defence, but it also means honest users burn budget on repeats).
* **The unit of privacy is a person (one national identifier)** at the participating hospitals; it assumes one identifier per person. DP protects the *released answers*; it says nothing about the PSI intersection that hospitals learn.
* Patients who are rare on *plaintext* quasi-identifiers (birth year, sex) are protected only through the aggregate interface — the interface never exports rows, but if the databases leak the plaintext columns are readable.
* **Timing has a residual.** Hospitals answer data-touching calls at public deadlines (`configs/policy.yaml: response_deadlines`), set for a 4-core machine, and run each of them alone (no other request runs at that hospital until its deadline has passed), so probing the hospital meanwhile shows only deadlines too. An overrun (an extreme noise draw, a slower or shared machine, a flood of requests whose bodies the hospital still decodes) shows which doubling of the deadline it fell in, and adds (1 + e^ε)·β per call to δ (SECURITY_THEOREMS.md, Theorem 2). β is estimated for the noise draw only and assumes each hospital has its own machine; a separate worker process on a dedicated core, or rate limiting in front of each hospital, would make it hold against a flooding coordinator. Deadlines add latency: every query waits for its prepare deadline (0.25 s plus the noise allowance), and a Laplace SUM over a field with a large bound (heart-failure NT-proBNP) needs ε ≥ 0.8 or the Gaussian mechanism. Whether a linkage is already cached still shows in the response time. Infrastructure failures are assumed independent of the data.

**Federated learning (stretch)**
* The noise (clipped updates + Gaussian) gives **client-level** DP: it hides a *whole hospital's* contribution, not individual patients. With three clients the ε needed for real protection costs most of the accuracy (AUC 0.727 → 0.53 at ε ≈ 5). Record-level DP-SGD is not implemented.
* Plain FedAvg shows the coordinator each hospital's update (evaluation only: strict hospitals refuse it); secure aggregation hides it, but updates are not verified (a malicious hospital can poison the model) and trained weights can memorise training rows (membership inference / inversion are not evaluated). Hospitals still accept zero noise and any number of rounds, and FL rounds are not charged to any budget.
* Training is an operator job. Handing weights to a *requester* would need its own DP budget and audit trail and is deliberately not exposed.
* The training registries are a separate, non-IID synthetic sample (see `synth/registry.py`), not the vertical A/B/C slices.

**System security**
* **Encryption at rest protects a stolen file, not a running service**: the key is in process memory; administrators of a hospital can read its data (they own it). AAD binds ciphertext to its *column*, not its *row*. No key rotation, no KMS/HSM.
* **PKI is a toy:** keys are unencrypted PEM files next to the CA key; no revocation, no rotation, certificates valid for a year.
* **Tokens:** JWTs cannot be revoked before expiry; no refresh flow. Service tokens have no replay cache (they are visible only inside mTLS and live 60 s).
* **Audit log:** truncating the *newest* entries is invisible without an externally stored head anchor; whoever holds the audit key can forge a whole chain; hospitals keep no audit of their own.
* **The dashboard's "ground truth (demo mode only)" toggle** reads the synthetic CSVs inside the dashboard process (`FEDHEALTH_DEMO_MODE=1`). It defeats the whole point of the system for whoever can run the dashboard that way; it is off by default, absent from the Compose file, and exists only to let you inspect the accuracy/privacy trade-off.
* **The Docker deployment was never executed** (Docker is not installed on the build machine): `docker-compose.yml` is validated statically — least-privilege mounts, no published hospital ports, no insecure routes (`tests/test_deployment.py`) — while the same topology is exercised by `scripts/run_local.py --secure` and `tests/test_e2e_tls.py`.
* **Availability / DoS** is out of scope. SQLite and in-memory protocol sessions are single-node; the login throttle is in-memory.
* **Other side channels** (CPU and memory contention between services on one machine, cache timing) are not considered (hospitals must run on separate machines; the in-process test harness runs all three in one interpreter); message sizes depend only on M and the query shape, and response times are covered above.
* **Synthetic data only (Synthea).** Synthea's disease modules are guideline-driven, so treatment and outcome patterns are cleaner than real records; outcomes are derived from its lab series (FEV1/FVC as the asthma/COPD proxy, almost no follow-up PHQ-9 for depression), adherence is a refill-coverage proxy, and SSNs make a perfect linkage key. No claim is made about real-world re-identification risk.

## 5. Questions a reviewer should ask (and the honest answers)

* *"Does the coordinator see patient data?"* — No row, ID, per-patient value, exact aggregate, cohort size or list size; it sees the public bound M and the noisy aggregate (SECURITY_THEOREMS.md lists everything).
* *"What if the coordinator colludes with a hospital?"* — Together they still see only noise that is ε-DP on its own, and no other hospital's inputs (Theorem 1, 2b). Two hospitals colluding break input privacy.
* *"Can the coordinator forge answers?"* — Yes. There is no verifiability of the computation.
* *"Is this production-ready?"* — No. It demonstrates the protocols, their composition and their tests; see the limitations above before reusing any of it.
